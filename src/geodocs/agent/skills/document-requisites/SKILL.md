# Реквизиты документа из названия

## Форматы, которые нужно распознавать

Реальные названия из базы (эталоны):

- «Правила землепользования и застройки городского округа Солнечногорск
  (изменения № 944 от 09.04.2026)» → doc_type=pzz, number=944,
  version_date=2026-04-09
- «Правила землепользования и застройки муниципального округа Шатура
  (изменения № 1069 от 08.06.2026)» → doc_type=pzz, number=1069,
  version_date=2026-06-08
- «Правила землепользования и застройки городского округа Коломна
  (изменения № 1198 от 17.04.2026)» → doc_type=pzz, number=1198,
  version_date=2026-04-17
- «Постановление о режимах использования земель (ЗОУИТ) 50-11/0020310-49»
  → doc_type=zouit_regime, number=50-11/0020310-49, version_date из карточки

## Правила извлечения

1. Номер — после «№» или «изменения №»; может содержать слеши и дефисы
   (50-11/0020310-49) — сохраняй как есть.
2. Дата — после «от» в формате ДД.ММ.ГГГГ; в version_date переводи в
   ISO ГГГГ-ММ-ДД.
3. Вид документа: «правила землепользования»/«ПЗЗ» → pzz; «генеральный
   план»/«генплан» → general_plan; «ЗОУИТ»/«режимы использования земель»
   → zouit_regime; «планировка территории» → planning_project.
4. Если номер или дата в названии отсутствуют — бери их из задачи
   (поля `number` и `version_date` уже точные, не выдумывай свои).

## Зачем это критично

- `check_local_store` и `search_document` ищут по точным реквизитам:
  неверный номер = гарантированный not_found.
- В MANIFEST реквизиты должны совпадать с реквизитами задачи — иначе
  приёмка не сможет сопоставить файл с версией.
